# Offline native upstream rehearsal adapter

`scripts/value_evaluation/study_upstream.py` drives the pinned native CLI against
a scripted loopback server. It is mechanical preparation only: no provider
forwarder, credential lookup, paid dispatch function or real funding allocation
exists. Import starts no process, listener or application. `paid` campaign mode
is refused. Synthetic microdollar admissions settle at zero; their limits are
fictional durability fixtures, not provider prices, available credit or proof
that the approved full batch is affordable.

This adapter depends on the separate `campaign_state.py` controller. It imports
no dated pilot runner, broker, ledger or allocation. All old outputs and financial
records remain untouched. A new explicit evidence directory and a new isolated
upstream worktree are required; existing attempts cannot be overwritten.

## Explicit invocation

`run_phase` requires the campaign, product/case/stage, owned workspace, exact
40-character upstream commit, complete tracked source hash map, executable paths
and matching hashes, new phase directory, UUID session, prompt bytes and authored
script actions. Executables are `cli`, `python`, `xelatex`, `pdftoppm`, `pdftotext`,
`pdfinfo`, `git` and `bash`; additional pinned support files use `support_000`,
`support_001`, etc. The caller must inventory all relevant runtime dependencies,
including DLLs, and retain the exact source/setup overrides. A supplied executable
hash list alone does not prove complete machine/runtime reproducibility.

The retained rehearsal uses upstream commit `64a6c90ec32438742ca62f8f30f55afea4435172`
plus four explicitly synthetic setup overrides: `CLAUDE.md`,
`.claude/skills/job-application-assistant/01-candidate-profile.md`,
`.claude/skills/job-application-assistant/02-behavioral-profile.md` and
`cv/main_example.tex`. The effective tracked-file hashes bind those overrides;
unchanged effective bytes do not mean a commit-clean upstream checkout. Scripted
cover content retains stock contact placeholders, so mechanical completion does
not establish factual contact accuracy or application quality.

Fit starts an isolated native session. Materials resumes only its explicitly
supplied owned environment. That environment is rebuilt from allowlisted values;
extra auth keys, outside HOME/config/temp directories and linked paths refuse.
Real inherited provider keys and user configuration are not used. The only API
key is an obvious fixed synthetic value for `127.0.0.1`. Retries, prompt caching,
fast mode, nonessential traffic and unreviewed settings/MCP sources are disabled.
This is application/process configuration, not an operating-system firewall
guarantee; independently verify the actual route and disclose observation limits.

Fit-only V07–V12 materials refuse before process creation. The controller admits
the exact frozen stage/order and every scripted model request. Parent drafting,
tool continuations and the named reviewer share stage and packet request caps.
There is no separate reviewer budget. Exact original body bytes are saved and
hashed before reservation, and one durable microdollar reservation precedes any
scripted response. Responses settle at zero real cost; interruptions retain
pending reservation/count state and never auto-replay.

## Narrow native contract

The pinned request contract requires the declared model, adaptive thinking with
omitted display, medium effort, the known context-management setting and exactly
32,768 maximum output tokens. Undeclared temperature/tool-choice settings refuse.
Tool definitions must be inert custom object schemas with
known fields/names. The CLI's `DeferredToolPlaceholder` advertisement is accepted
only as a definition; execution remains forbidden. External/server tools and
unexpected visual input are refused.

Authored actions may use owned Read/Write/Edit/Glob/Grep, the named application
reviewer and exact known Bash compiler/checker forms. Linked/outside/protected
paths and edits to any frozen source file are refused. No arbitrary executable,
network command, shell expansion, recursive deletion or implicit command expansion
is allowed. Tool arguments have strict allowlists; background execution,
disable-sandbox flags and command timeouts above 120 seconds refuse. Compiler calls keep `-no-shell-escape`; Python runs only the pinned
native PDF and layout checkers. This is not a general shell sandbox or a paid
agent runner. A future broader tool surface requires separate review.

The loopback server handles only exact native message/beta and mechanical token
count routes. It never forwards. Accepted sockets have bounded read/write timeouts;
the owned broker has bounded shutdown observation. Request/header errors produce
fixed sanitized refusal classes/reasons and code locations, never raw provider
headers, credentials or exception text. Token counts are scripted mechanical
counts, not real provider token/pricing evidence.

## Completion and evidence

A successful phase requires native exit zero, a non-error success result, no
permission denial, all scripted actions delivered, all emitted tool results
returned without error, a named-reviewer request when requested, settled state,
unchanged pinned source/runtime bytes and controller stage completion. Exit zero
or a model summary alone is insufficient. Scored application quality cannot be
inferred from authored scripted output.

Preserve first drafts/revisions/final bytes, native checker and visual reads,
tracker/archive records, original stdout/stderr, request/response hashes,
source/runtime/prompt/action hashes and UTC phase receipts. Independent QA must
inspect every actual final PDF page and verify process/listener terminal state.
A full mechanical proof exercises fit then native resumed drafting, named review,
both PDF compiles, extraction/layout checks, every-page Read and recordkeeping.
Do not label an earlier partial or failed proof as complete.

On timeout or interruption, cleanup targets only the exact owned process tree;
the direct PID and cleanup disposition remain in the receipt. A tree-stop failure
still attempts bounded direct-owner cleanup but retains unknown descendant state
for independent inspection. The adapter never claims complete descendant absence
from a direct-process exit alone. Unknown state, stalled cleanup, retained partial
outputs, locks or financial reservations require review before any next attempt.


Tests use synthetic temporary files and loopback-only HTTP; they do not run the
real CLI or forward provider requests. They cover exact bytes, shared reviewer
counts, unknown freezes, strict schemas, tool/path restrictions, inherited-key
exclusion, session reuse, fit-only/paid refusal and owned-process failure cleanup.
Actual native-runtime rehearsal is separate evidence and must bind the exact
adapter/script/runtime/source hashes after review.

Retain owned worktrees, runtime directories, journals/heads, failed originals and
proof receipts through independent review and campaign closeout. Record exact

by this module. Never remove historical evidence or shared toolchains as part
of a rehearsal cleanup.
